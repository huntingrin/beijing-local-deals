# 三路搜索与降级

## 网页

组合：北京/区县 + 品类/品牌/场馆 + 优惠/消费券/免票/惠民 + 当前月份；按用户日期核对原始条款。优先品牌/场馆、北京市政府、文化旅游主管部门等原始公告。网页转载也需追溯出处；搜到公众号原文时将其归入公众号内容来源，不虚增独立证据。

官方入口线索（不是永久有效的优惠清单）：北京市政府 https://www.beijing.gov.cn/ ，文旅北京 https://whlyj.beijing.gov.cn/ ，北京旅游网 https://www.visitbeijing.com.cn/ ，北京日报 https://news.bjd.com.cn/ 。品牌、场馆自身公告按需求实时检索。

## 小红书

有现成MCP/已授权接口时先检查登录，再搜索并读取相关笔记。没有能力就记录unavailable，不要求安装特定MCP。排序/时间筛选若工具不支持，普通搜索后按实际日期筛选；不要循环重试不支持的参数。笔记和评论是线索/体验，不代表所有账号都能领。无需读取私信、点赞或发布。

## 微信公众号

默认目标：发现原文所述在活动期的北京优惠，输出可扫码阅读原文章的普通二维码，不要求自动领取。

已验证路径：搜狗微信收录内容 → 原文URL → 正文 → 具体有效优惠 → 文章入口码。2026-10-16研究共9次查询90条原始候选；8次初始取文6篇可读、2篇验证壳；1个文章二维码经用户确认打开。它只证明一个案例，不证明长期稳定或当前可领。后续HTTP受阻与用户微信扫码成功可以同时成立。

辅助工具：`python scripts/weixin.py search '北京 咖啡 优惠 <当前年月>' --out <新目录> --limit 3`，随后 `python scripts/weixin.py article '<原文URL>' --out <新目录>`。顺序低频，最多一页、1–10个结果，保留匿名会话、请求时间与失败，不携带用户登录信息。解析逻辑参考固定版本 [wx-search-cli](https://github.com/tjx666/wx-search-cli/tree/70b75b71384b4bcfce86be744b685f02f9440c16)，许可证见third_party；本项目Python实现的离线测试不等于其在线稳定性已验证。

辅助工具自动保存正文、图片URL、链接和小程序标签，但不下载并判定图片、也不自动理解优惠。由Agent核对正文、日期和优惠，再选择文章入口或取得原始活动码。小程序标签只作导航线索。

错误必须区分：blocked、http_error、network_error、parse_error、empty_results、article_ok、media_only。无正文/HTML200验证壳不可冒充成功。已解析的候选在中途失败时保留，但状态为partial或blocked。

受阻停止记录默认位于 `~/.local/state/beijing-local-deals/weixin-stop.json`（可通过BEIJING_DEALS_STATE_DIR指定宿主统一状态目录，不能每次换目录规避停止）。`python scripts/weixin.py stop --reason '沿用前序研究的验证阻塞'` 可以迁移已知停止状态。两类域名共用停止状态，存在时不发请求。用户正常完成验证并确认后，才可归档该记录，并重新进行一次低频检查；本工具不自动清除、不提供解码验证或代理轮换。

本轮受阻后可继续网页/小红书寻找其他独立机会；不要用另一个客户端访问同一受阻目标。历史文章只能作为线索/回放；若无法重新读取，应明确本次未刷新，不能改写checked_at伪装刚验证。

搜狗索引不是微信客户端搜一搜，不覆盖全部公众号/小程序。OpenCLI、其他搜狗包装器不算另一独立渠道；客户端操作不是本技能必需依赖。只有原文中已有链接或码才能交付，无法生成码时给文字路径并标限制。
